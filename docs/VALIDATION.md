## Windows実機テストの再実行

`scripts/windows-smoke.ps1` が専用の一時フォルダーにexeをコピーし、生成したPDFを起動引数で渡します。`scripts/windows-smoke.cjs` がこのテストプロセスだけに設定したWebView2のローカルデバッグポートを使い、UI操作と保存ファイルを検証します。製品の通常起動時にデバッグポートを有効にするコードはありません。

WSLから直接起動すると、この環境ではプロセスが非対話Session 0に入りWebView2の起動が完了しませんでした。ログイン中のユーザーの対話セッションで同じexeを実行すると正常に動作しました。この環境の自動テスト用に `scripts/windows-interactive-test.ps1` を用意しました。現在のユーザーとして昇格なしの一時タスクを登録し、テスト完了時にタスクを削除します。Windowsでログインした状態が必要です。WebView2プロファイルは各テスト実行専用に生成・削除します。保存ファイルの検査は未保存マークが消えた後に行い、前回のステータス表示を保存完了と誤認しないようにしています。

```powershell
# release版を事前にビルドしてから実行
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows-interactive-test.ps1
# debug版ビルドとViteサーバー起動後
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows-interactive-test.ps1 -Mode debug
```

スクリプトはこのワークスペースのクロスビルド出力と `C:\Program Files\nodejs\node.exe` を使用します。別環境では `windows-smoke.ps1` の実行ファイルパスを合わせてください。スクリーンショットは `.tools/windows-native.png` と `.tools/windows-native-advanced.png` に保存します。
