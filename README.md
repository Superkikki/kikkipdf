# Kikki PDF

Tauri 2 / React / TypeScript / Vite / Rust で作った、ローカル処理のPDF編集デスクトップアプリです。Windows 11を第一対象とし、画面のデザイン・アプリの編集モデル・操作コマンドは独自実装です。PDFの解釈・描画・書き出しにはOSSを使用しています。

**バージョン0.9.7は実際のPDFを開いて編集・保存できる初期実用版です。Acrobat Pro相当の全機能・互換性を達成した完成製品ではありません。** 対応範囲を限定した既存文字の直接編集、墨消し時の画像化など、以下の制約を確認してください。

このワークスペースのWindows配布物は [0.9.7インストーラー](artifacts/windows/Kikki%20PDF_0.9.7_x64-setup.exe) と [圧縮ZIP](artifacts/windows/Kikki%20PDF_0.9.7_x64-setup.zip) です。チェックサムは隣の `SHA256SUMS-0.9.7.txt` に記録しています。0.9.4以降のWindows配布物もGit管理に含めます。

## セットアップ（Windows 11）

必要なもの:

- Node.js 22.12以降（24 LTS推奨）とnpm
- Rust stable（MSVC toolchain）
- Visual Studio Build Tools の「C++によるデスクトップ開発」とWindows SDK
- Microsoft Edge WebView2 Evergreen Runtime

[Tauri公式の前提条件](https://v2.tauri.app/start/prerequisites/)も参照してください。

```powershell
npm ci
npm run assets
npm run desktop
```

`npm run assets` はPDF.jsのCMap・標準フォント・WASM、Noto Sans JP、TesseractのWorker/WASMと日本語・英語の認識データを `public/assets` に配置します。初回セットアップにはネット接続が必要です。ダウンロードしたフォント・言語データのSHA-256を `scripts/asset-lock.json` で検証します。配置後のアプリはPDFの内容を外部サーバーへ送信せず動作します。

0.4以前の開発環境から更新した場合も、`npm run assets` を再実行してください。日本語フォントをNoto CJK Sans 2.004の静的Regular OTFへ変更し、フォントの省略埋め込みを停止して、保存PDFで字形が欠ける問題を修正しました。日本語を含むPDFは完全なフォントの埋め込みでサイズが増える場合があります。新しいファイルの整合性確認後に、旧生成フォントを除去します。原本PDFや編集プロジェクトは対象外です。フォントの出典は [LICENSES/NotoSansJP-SOURCE.md](LICENSES/NotoSansJP-SOURCE.md) に記録しています。

## 開発・テスト

```powershell
npm run desktop          # Tauriウィンドウを使う通常の開発
npm run dev              # UIだけのブラウザー検証用。デスクトップ版とは異なる
npm run check            # ESLint、ユニットテスト、TSチェック、Vite production build
cargo test --manifest-path tests/native/Cargo.toml
npx playwright install chromium
npm run test:e2e
```

ブラウザー検証モードではファイル選択とダウンロードを代替利用します。暗号化、最近のファイル、ネイティブの終了確認・保存権限などはTauri版の機能です。テスト用既存ブラウザーを使う場合は `CHROMIUM_PATH` に実行ファイルのパスを設定できます。

macOSではXcode Command Line Tools、LinuxではGTK 3、WebKitGTK 4.1、librsvgなどの開発パッケージが必要です。UI・モデル・Workerは共通ですが、この2 OSの配布パッケージはまだ実機検証していません。

## Production build

```powershell
npm ci
npm run assets
npm run desktop:build
```

通常のWindows/MSVCビルドでは以下を生成します。

- `src-tauri/target/release/kikki-pdf.exe`
- `src-tauri/target/release/bundle/nsis/Kikki PDF_0.9.5_x64-setup.exe`

NSISはユーザー単位でインストールする日本語・英語対応のインストーラーです。OSSのライセンス本文も同梱します。現時点ではコード署名していません。WebView2未導入の環境ではインストーラーがRuntimeの取得を必要とするため、オフラインでインストールするときは事前にRuntimeを用意してください。

### PDFの既定アプリに設定

0.8.2以降のインストーラーは `.pdf` / `.kpdf` を開けるアプリとしてKikki PDFを登録します。「設定」→「アプリ」→「既定のアプリ」で `.pdf` を検索し、Kikki PDFを選択してください。PDFの右クリック→「プログラムから開く」からも選択できます。登録時に現在の既定アプリを変更しません。

0.8.1以前で候補に表示されない場合は、最新のインストーラーで上書きインストールしてください。設定画面を開いていた場合は閉じて開き直してください。exeの直接起動や開発モードだけでは登録されません。

Windows以外からのクロスビルドは [Tauri公式のWindows配布手順](https://v2.tauri.app/distribute/windows-installer/)に従い、Clang/LLVM、NSIS、cargo-xwinを用意して実行します。

```sh
rustup target add x86_64-pc-windows-msvc
cargo install cargo-xwin --locked
npm run tauri -- build --runner cargo-xwin --target x86_64-pc-windows-msvc
```

変更履歴は [CHANGELOG.md](CHANGELOG.md) にあります。

このワークスペースで使ったローカルツールの再実行用スクリプトは `scripts/build-windows-local.sh` です。`.tools` は開発環境のみに使い、アプリには含めません。Windows上の継続ビルド設定は `.github/workflows/windows.yml` にあります。GitHub上でのCI実行結果は未確認です。

## 基本操作

1. 「開く」、Ctrl+O、PDFのドラッグ＆ドロップ、またはexeへのPDFパス引数で開きます。
2. 左側のサムネイルをクリックして移動。サムネイルをドラッグするとページ順を変更できます。挿入線の位置に移動し、Alt＋↑／↓でも前後へ移動できます。
3. 「ページ管理」で回転・複製・削除・空白ページ・結合・抽出・分割・トリミングを操作します。
4. 「編集」「注釈」でツールを選択し、ページ上をクリックまたはドラッグして配置します。
5. 追加オブジェクトを選び、右パネルで内容・座標・サイズ・色を調整します。ドラッグで移動、右下のハンドルでサイズ変更、右クリック→「削除」またはDeleteで削除できます。右クリックの削除は、矩形・円・線・テキスト・画像・注釈に共通です。描画ツールの選択中も使え、Ctrl+Zで元に戻せます。
6. Ctrl+Sで保存、Ctrl+Shift+Sで別名保存。Ctrl+Z / Ctrl+YでUndo/Redo。

ページ範囲は `1-3,5` の形式で、空欄は全ページです。範囲は1始まり、内部モデルは0始まりです。通常の「分割」は指定ページごとに保存先を選びます。「分割ZIP」はまとめて保存できます。

## 0.9.0の閲覧・操作改善

- PDF表示領域でCtrlを押しながらホイールを動かすと拡大縮小できます。タッチパッドの2本指ピンチにも対応します。倍率は25〜400%で、カーソル付近の位置を保持します。Ctrlなしの2本指スクロールはページのスクロールに使えます。
- Windowsのネイティブファイルドロップと干渉しないポインター操作で、サムネイルを並べ替えます。上下の挿入線を目印にドロップし、リスト端では自動スクロールします。Escで中止でき、Tabでサムネイルを選んでAlt＋↑／↓でも移動できます。並べ替えはUndo/Redo・PDF保存に反映されます。

- 文書名の右側の「サイドバー」「プロパティ」で左右のパネルを開閉できます。狭い画面ではプロパティを閉じた状態から開始し、追加オブジェクトを選択すると開きます。
- 連続スクロールでも現在ページ・下部のページ番号・左のサムネイルが追従します。別のページへスクロールするとオブジェクト選択を解除します。サムネイルはTabで選び、Enter／Spaceで移動できます。
- 幅合わせ・全体表示でも下部に実際の倍率を表示します。＋／−は表示中の倍率から25ポイントずつ変更し、通常倍率の範囲は25〜400%です。ズーム・パネル開閉・ウィンドウサイズ変更でも、可能な範囲で読んでいた位置を保持します。
- Ctrl+F（macOSはCmd+F）でサイドバーの文書内検索を開き、検索欄を選択します。Enterで最初の結果へ移動し、続けて押すと次の結果へ移動します。Shift+Enterは前の結果へ移動し、先頭／末尾で巡回します。
- メニューは外側クリックやEscで閉じられます。ページ番号は入力途中で空にでき、有効な番号では即時移動し、Enter／フォーカス移動で空欄や範囲外の番号を補正します。

これらの機能は0.9.0のインストーラーに含まれます。

## 0.9.0のフォーム設定編集

- 「ツール」→「フォーム入力」→「フォームを作成・編集」で「既存の入力欄」を選びます。「入力欄の設定」で名前・必須・読み取り専用を変更し、「設定を適用」でまとめて反映します。同じ項目の複数ページの欄へ適用し、配置は従来どおり各欄で変更できます。
- 文字欄は複数行・最大文字数を変更できます。最大文字数の空欄は制限なしです。現在の入力値より短い制限は拒否するため、先に値を修正してください。
- ドロップダウン／リストは1行に1つの選択肢と複数選択を変更できます。空欄・重複は拒否します。削除した選択肢の値は解除し、複数選択を解除すると現在の先頭の選択だけを残します。「元の設定に戻す」でも、戻した選択肢に含まれない値は解除します。
- Undo/Redo・元の設定への復帰・PDF保存後の再入力・`.kpdf`保存／再読込・ページ複製／抽出・文書結合に対応します。フィールド名が重複すると保存時に連番が付きます。
- ラジオボタンの選択肢変更は未対応です。表示名・保存値が異なる選択欄の入力・選択肢編集・複数選択には0.9.6から対応します。

## 0.9.7で追加した操作

- 「ツール」→「既存画像」で画像を選択し、右パネルの「画像を取り出す」で画像データだけを保存できます。元の画像は元解像度の透過PNGへ変換し、ページの文字・背景・重なっている図形を含めません。差し替え済みのPNG／JPEGはそのデータをそのまま取り出します。
- 「画像を複製」またはCtrl+Dで独立した画像を追加。Ctrl+C／X／Vで別ページ・別文書へ貼り付けられます。元の配置サイズを保持し、貼り付け時は12ptずらします。コピー元の共有画像は変更しません。
- Undo/Redo・プロジェクト復元・PDF保存に対応。削除済みの画像は先に復元してください。取り出した元画像は2000万画素・各辺16384画素・PNG32MBまでで、ステンシル画像は未対応です。元のページ上の透明度・描画効果・重なり順は複製に引き継がず、追加画像として最前面に置きます。

## 0.9.6で追加した操作

- 表示名と保存値が異なる既存ドロップダウン／リストを正しく入力できます。ページ上とフォーム画面の両方で表示名を選び、元の保存値をPDFに記録します。
- 「フォームを作成・編集」の設定から表示名と保存値を個別に変更し、選択肢を追加・削除できます。保存値の空欄・重複は拒否し、削除した保存値の選択だけを解除します。
- 複数選択・既定値・Undo/Redo・元の設定への復帰・`.kpdf`復元・PDF保存・固定保存に対応します。保存PDFの外観にも表示名を使用し、選択位置を保存値と一致させます。

## 0.9.5で追加した操作

- 「既存画像」で使用箇所を選び、プロパティの「画像を差し替える」でPNG／JPEGを指定します。同じ元画像を使う他の箇所や別ページを保ち、選択した位置・サイズ・描画順で差し替えます。元の画像ボックスへ合わせるため、縦横比が異なる画像は伸縮します。
- 「元の画像データに戻す」は移動・サイズ変更を残して差し替えだけを解除します。「元の画像に戻す」は位置・サイズ・差し替え・削除をすべて解除します。Undo/Redo、削除した画像への差し替え、PDF・`.kpdf`保存と再編集に対応します。
- PNGの透明度も保存します。差し替え画像は1件32MB・6400万画素までです。画面・サムネイル・検索のプレビューは、差し替えた元の描画命令とリソースから生成します。すべての使用箇所を差し替えた場合、不要になった元画像・マスクの参照とストリームを出力PDFから除きます。

## 0.9.4で追加した操作

- 「ツール」→「既存文字」でIdentity-Vの縦書き本文をダブルクリックし、文字・位置・サイズ・色を変更できます。元の文字送りを計算して元文字を除き、後続文字の位置を保持します。元フォントの完全再現ではなく、選んだフォントで描き直します。
- テキストのプロパティ「文字の方向」で横書き／縦書きを選択します。縦書きは上から下、次の列は右から左へ配置します。「高さに合わせて折り返す」「列間」「文字に合わせて幅を調整」で配置を調整できます。改行でも次の列へ移ります。
- Noto Sans JPまたは登録した静的TTF／OTFを使用し、句読点・括弧・長音などの縦書き用字形を画面とPDFへ反映します。文字は画像化せず、保存PDFでも検索・抽出・再編集できます。Undo/Redoと`.kpdf`保存にも対応します。
- 基本的な縦書きが対象です。縦中横・ルビ・欧文の横倒し・高度な禁則処理は未対応です。太字・斜体は対応する登録フォントを選びます。1オブジェクト10000文字までで、複数字形が必要な書記素やUnicode対応が曖昧な字形は拒否します。OCRの縦書き最適化とは別機能です。

## 0.9.3で追加した操作

- 「ツール」→「既存画像」で編集可能な画像に枠を表示し、ダブルクリックまたはEnterで選びます。ドラッグ、右のX・Y・幅・高さ、サイズ変更ハンドルで位置とサイズを変更できます。
- 「削除」でその使用箇所の画像描画を除き、「元の画像に戻す」で元の配置と描画を復元します。Undo/Redo・PDF保存・`.kpdf`保存に対応します。
- 元の画像・画素・マスクを保ち、同じ画像を使う別の箇所やページは変更しません。入れ子のForm XObjectにも対応し、所属する部品のBBoxの範囲内で編集します。表示中のページ・サムネイル・検索を更新します。
- 対象は平行移動・正の水平拡大縮小で配置された画像XObjectです。回転・反転・傾斜、明示的クリッピング、透明グループ、インライン画像など特殊な描画は拒否します。画像のコピー・複製は0.9.7から独立した追加画像として対応します。元の画像描画の重なり順の変更は未対応です。差し替えは0.9.5から対応します。画像削除は墨消しとは別機能で、原本・注釈・他の使用箇所・プロジェクトや履歴の画像データの削除は保証しません。

## 0.8.0で追加した操作

- 「ツール」→「既存文字」を選び、PDF本文の文字領域をダブルクリックします。右プロパティで文字列・位置・フォント・サイズ・色を変更できます。英字を日本語へ変更する場合は、日本語を含むフォントを選んでください。
- 元のTj/TJ/引用符の文字描画命令から文字列を除き、元フォントの幅・文字間隔から計算した数値TJで後続文字の位置を保持します。編集後の文字は新しい描画命令で保存します。白い背景マスクを使用せず、ページの背景色・画像を保持します。
- PDF.jsが連続した複数の描画命令を一つの文字領域にまとめる場合も、文字列と位置が一致する範囲をまとめて編集できます。ページ回転・ズーム・元CropBox、Undo/Redo・削除・復元・ページ複製・抽出・`.kpdf`保存に対応します。コピーした編集文字は独立した追加テキストになります。
- 未保存の表示・サムネイル・検索も、元文字を取り除いたページをWorkerで生成して更新します。対象の元文字はそのページの検索・抽出から除かれます。「元の文字に戻す」は元の描画を復元し、「削除」は対象文字の削除を保持します。
- 保存時に元描画命令のSHA-256・位置・元文字列を再確認します。参照の不一致や未対応の描画では保存を停止します。対応する形式と除外する形式は以下の互換性欄に記載しています。
- 従来のマスク方式は「見た目の置換」として明示的に選ぶ別ツールです。未対応文字の直接編集から自動で切り替えることはありません。**直接編集は墨消しではなく、原本・他の箇所・注釈・OCR・メタデータ・プロジェクト・履歴には元の情報が残り得ます。**

## 互換性と現在の制約

- **通常保存は新しいPDFを組み立てます。** デジタル署名、アクセシビリティ構造タグ、ポートフォリオ、レイヤー、文書レベルのアクションなどの完全保存は未対応です。既存の暗号学的署名の有効性は維持しません。重要な原本は別名保存で保持してください。
- 元のページ上のテキスト・ベクター・画像は通常保存時にページコピーで保持します。オブジェクト編集用のモデル/Undo履歴はPDFに埋め込みません。保存後に開き直した追加文字や図形は元PDFの内容となり、以前の編集オブジェクトとしては選択できません。再編集用には別途`.kpdf`を保存してください。
- **標準AcroFormは再入力可能な状態で保存します。** フォーム画面の「固定して保存」で明示的にflattenすることもできます。フィールド作成は5種類に対応し、位置・サイズ・選択肢・必須・読み取り専用・複数行・最大文字数・複数選択を設定できます。既存欄の移動・サイズ変更にも対応し、0.9.0では上記の設定編集も可能です。既存項目の種類変更、別ページへの配置変更、JavaScript計算は未対応です。ラジオの選択肢変更は拒否します。表示名と保存値が異なる選択欄は、画面に表示名を出し、PDFへ保存値を記録します。既存欄の画面表示は入力用の簡易表示で、装飾・欄自体の回転・特殊な文字組みを完全には再現しません。XFAの保存はエラーで停止します。署名フィールドを含むPDFは通常保存を拒否し、固定保存を選んだ場合も暗号学的署名を保持しません。既存フィールドの値の外観は保存後に更新します。日本語の再入力を可能にするため完全なフォントを埋め込み、出力サイズが増える場合があります。同名フィールドの結合時には名前に連番を付けます。複製した元PDFページのフィールドは同じ値を共有します。
- **直接編集はページ直下と対応するForm XObject内の横書き・対応する縦書きの塗り文字が対象です。** Type1/TrueTypeのWinAnsi・MacRoman・標準エンコーディングのASCII、Identity-H／Identity-V＋ToUnicodeのType0/CIDフォントに対応します。0.9.1ではToUnicodeの文字対応表と元のWidthsを検証できる独自エンコーディング（Encoding Differencesなど）・標準エンコーディングの非ASCII文字も編集できます。未知の文字対応や幅は推測せず拒否します。0.9.2ではForm XObjectの入れ子・座標変換・リソースをたどり、編集した呼び出しだけを複製して保存します。同じ部品を使う別の箇所やページは保持します。対象はBBox内の横書き・対応する縦書き文字で、外部参照・透明グループ・回転した部品は拒否します。幅情報を確認できないフォント、対応表・幅を検証できない独自エンコーディング、Identity-V以外の縦書き・傾斜/回転した文字、透明グループなど特殊なForm XObject内の文字、文字クリッピング、ActualText、特殊な描画効果は対象外です。標準14書体の埋め込みなしType1だけは標準の幅情報を使用します。インライン画像や特殊なUserUnit倍率を含むページ、安全に解析できない命令のページも拒否します。置換後は選択したフォントで描き直すため、元の埋め込みフォント・カーニング・横倍率・字形を完全再現するものではありません。
- 「見た目の置換」は元の文字列を保持する背景マスク方式です。検索・抽出で元文字を取得し得ます。背景が単色でないページには適しません。Word型の段落再レイアウト、ベクターの直接編集、未対応形式のContent Stream編集は未実装です。
- Noto Sans JPを同梱し日本語を出力します。静的TTF／OTFの登録と完全埋め込みに対応しますが、システムフォントの自動列挙、TTC・可変・カラーフォント、字詰め・高度な文字組み・縦中横・ルビは未対応です。登録フォントは追加文字・見た目の置換・OCR文字に適用でき、フォーム用フォントの変更は未対応です。欧文標準フォントに日本語を指定すると書き出しエラーになります。日本語と登録フォントの横書きの太字・斜体は見た目を合成します。縦書きでは対応する登録フォントを選びます。自動折り返しは横書きでは幅、縦書きでは高さを使い、タブは4個の空白へ変換します。禁則は基本的な句読点・括弧についての簡易処理です。極端に狭いボックスでは1文字が幅を超える場合があります。画面の標準欧文フォントにはOSの代替フォントを使うため字形が多少異なりますが、行ごとの幅・改行位置は保存用フォントで計算します。完全埋め込みによりPDFとプロジェクトのサイズが増えます。
- 矩形・円・直線・矢印はページ描画として保存します。蛍光ペン・下線・取り消し線・手描きはそれぞれHighlight / Underline / StrikeOut / Ink注釈、付箋はText注釈として保存します。外観ストリームも生成します。文字選択注釈は隣接する文字領域をまとめ、行単位の注釈として保存します。コメント返信スレッドの保持は未対応です。画像と手描きによる署名は「デジタル署名」ではありません。
- しおりの移動先はページ単位です。元のズーム・スクロール位置・外部URLのしおりは保持しません。ページ内の通常のGoToリンクは並べ替え後のページへ再接続し、削除された移動先は除きます。HTTP(S)/mailtoリンクは保持します。Launch/JavaScriptなどのアクションや注釈の返信・Popup関連は保存しません。
- 編集プロジェクトは展開後512MBまで、内部JSONは16MBまでです。**元PDFや見た目の置換前の内容を含み、暗号化されません。** 墨消し適用済みPDFの代わりにプロジェクトを共有しないでください。破損検出のハッシュは署名・改ざん認証ではありません。
- 一括画像出力は画像の合計512MBまで、各ページ2000万画素まで。印刷は準備する画像の合計1億2000万画素までです。範囲を分けて大きな文書を処理してください。印刷用データは印刷終了イベントか次の印刷準備時に解放します。
- **トリミングは表示領域の変更だけです。** 元の内容の削除には使用できません。
- **墨消しは品質と機能を引き換えにした画像再構成方式です。** 元のContent Stream・画像・OCR・フォーム・添付・メタデータを出力にコピーしません。出力は検索・選択・リンク・フォームのない画像PDFになります。通常最大180 dpi、巨大ページは画素数制限で低下します。領域外の同じ情報、元ファイル、バックアップ、復旧データの削除は保証しません。保存した出力全体を確認してください。ベクターを保つ選択的な安全な墨消しエンジンは未実装です。
- OCRは最大144 dpiで処理し、誤認識や位置ずれがあり得ます。このアプリで追加した認識文字は「OCR校正」で修正できます。既存PDFに埋め込まれたOCR層の校正、縦書きの最適化、手書き認識専用モデルは未実装です。通常PDFを再び開いた場合は元PDFの文字となるため、校正を続けるには`.kpdf`も保存してください。認識文字を修正しても元のスキャン画像は変化しません。
- 復旧状態と登録署名はWebViewのローカルIndexedDBに保存します。**暗号化PDFを開いた場合も復旧データは平文です。** パスワードそのものは復旧状態・履歴・ログへ保存しません。OSのディスク暗号化を必要に応じて併用してください。
- 保存先の一時ファイルは同じディレクトリに作成し、同期後に置換します。通常終了・通常の失敗では削除しますが、電源断/プロセス強制終了での残留やストレージ上の完全消去は保証しません。
- 300ページの高解像度同時描画はしませんが、元のPDFバイト列と編集モデルはメモリーに保持します。保存Workerには入力がコピーされます。数GB級PDF向けの部分読み込み、ディスクバックドキャッシュ、メモリー上限管理は未実装です。
- Office変換と暗号学的電子署名は `src/security/contracts.ts` に追加プロバイダーの境界を用意しています。変換/署名エンジン自体は含めていません。

添付ファイルは名前ツリー・文書のAF・ページのFileAttachmentを読み取り、通常保存で保持します。同名ファイルには番号を付けます。追加と取り出しは1件128MBまで。ページ抽出・分割には添付を含めません。外部ファイル参照、PDFポートフォリオの分類、ページや構造要素のAF関連は未対応です。添付を削除したPDFでは参照と対応する埋め込みストリームを除きますが、`.kpdf`・Undo・復旧状態には元データが残ります。機密情報を共有する際は最終PDFを確認してください。

リンクの枠は編集画面だけに表示され、PDFには透明なLink注釈を保存します。新規リンクと変更した文書内リンクはページ全体への移動です。0.9.0では「ツール」→「リンク管理」で既存リンクのX・Y・幅・高さをpt単位で変更でき、「元の配置に戻す」で配置だけを復帰できます。座標は元のCropBoxの左上を基準とし、ページ回転前の値です。配置変更はPDF保存後に反映され、Undo/Redo・`.kpdf`保存にも対応します。0.9.0のインストーラーに含まれます。

## アーキテクチャ

```text
React UI → Command → History / DocumentModel → PDF export Worker → native atomic save
               ↑              ↓
          Undo / Redo     local recovery (IndexedDB)

PDF.js Worker: ページ描画、テキスト抽出、検索
Tesseract Worker/WASM: OCR（同梱言語データ）
Rust: ファイル選択・読み書き許可、バイナリIPC、暗号化、原子的置換
```

- `viewer/`: 表示、検索、座標変換、遅延描画
- `text/`: 画面と保存で共有する文字レイアウト、フォント選択、専用Worker
- `fonts/`: ローカルフォント検証、埋め込み権限、登録コマンド、一時FontFaceの管理
- `direct/`: 独自のContent Stream字句解析、元フォントの幅・ToUnicode解析、元文字参照、描画命令の置換。仕様は [PDF Reference](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.6.pdf) に基づき、Adobeの実装コードは使用していません。
- `editor/`: 操作の調整、選択オブジェクト、既存文字エンジン
- `pages/`, `annotations/`, `attachments/`, `links/`, `forms/`, `ocr/`, `redaction/`: 各機能
- `commands/`: モデル変更、履歴、キャンセル
- `state/`: 中央モデル、外部ストア、復旧保存
- `export/`: pdf-lib処理とWorker境界
- `platform/`, `src-tauri/src/`: ネイティブI/O・暗号化
- `components/`: メニュー、ツールバー、サイドバー、ダイアログ、プロパティ

モデルの座標は元ページのCropBoxを基準にした左上原点のptです。ページ回転は別プロパティで管理し、表示と保存時に変換します。元のバイト列はコマンドで書き換えず共有します。保存したリビジョンを識別し、別名保存した後にUndoしても保存先が原本に戻らないようにしています。

## セキュリティ設計

Tauriの権限はウィンドウタイトル・終了・イベントに限定し、汎用shell/任意コマンド実行APIは公開していません。ファイルアクセスはネイティブの選択/ドロップ/起動引数/最近の文書で許可したパスだけです。別名保存先はネイティブダイアログで選び、一度限りのトークンを発行します。通常保存のデータはバイナリIPCで渡します。CSPはローカル資産とIPCに限定します。PDFのスクリプトや外部リンクを実行する機能は設けていません。

## 検証結果

検証環境・実行コマンド・結果は [docs/VALIDATION.md](docs/VALIDATION.md) を参照してください。ビルド成功とWindows画面の起動成功は別々に記録します。テストで使用するPDFはコードから生成したデータで、ユーザーの文書は使用していません。

## アプリ名の変更

`src/config.ts` の `APP_NAME` と `src-tauri/tauri.conf.json` の `productName` / ウィンドウ `title` を変更します。アプリの識別子 `io.kikki.pdf` を変えると既存の設定/復旧データの場所も変わります。実行ファイル名も変更する場合は `src-tauri/Cargo.toml` のpackage名を変更してください。
