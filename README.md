# Kikki PDF

Tauri 2 / React / TypeScript / Vite / Rust で作った、ローカル処理のPDF編集デスクトップアプリです。Windows 11を第一対象とし、画面のデザイン・アプリの編集モデル・操作コマンドは独自実装です。PDFの解釈・描画・書き出しにはOSSを使用しています。

**バージョン0.4.0は実際のPDFを開いて編集・保存できる初期実用版です。Acrobat Pro相当の全機能・互換性を達成した完成製品ではありません。** 既存文字の見た目による置換、墨消し時の画像化など、以下の制約を確認してください。

このワークスペースで生成・検証したWindowsインストーラーは `artifacts/windows/Kikki PDF_0.4.0_x64-setup.exe` です。隣の `SHA256SUMS.txt` にチェックサムがあります。

## セットアップ（Windows 11）

必要なもの:

- Node.js 22.12以降（24 LTS推奨）とnpm
- Rust stable（MSVC toolchain）
- Visual Studio Build Tools の「C++によるデスクトップ開発」とWindows SDK
- Microsoft Edge WebView2 Evergreen Runtime

[Tauri公式の前提条件](https://v2.tauri.app/start/prerequisites/)も参照してください。

```powershell
npm ci
npm run assets
npm run desktop
```

`npm run assets` はPDF.jsのCMap・標準フォント・WASM、Noto Sans JP、TesseractのWorker/WASMと日本語・英語の認識データを `public/assets` に配置します。初回セットアップにはネット接続が必要です。ダウンロードしたフォント・言語データのSHA-256を `scripts/asset-lock.json` で検証します。配置後のアプリはPDFの内容を外部サーバーへ送信せず動作します。

## 開発・テスト

```powershell
npm run desktop          # Tauriウィンドウを使う通常の開発
npm run dev              # UIだけのブラウザー検証用。デスクトップ版とは異なる
npm run check            # ESLint、ユニットテスト、TSチェック、Vite production build
cargo test --manifest-path tests/native/Cargo.toml
npx playwright install chromium
npm run test:e2e
```

ブラウザー検証モードではファイル選択とダウンロードを代替利用します。暗号化、最近のファイル、ネイティブの終了確認・保存権限などはTauri版の機能です。テスト用既存ブラウザーを使う場合は `CHROMIUM_PATH` に実行ファイルのパスを設定できます。

macOSではXcode Command Line Tools、LinuxではGTK 3、WebKitGTK 4.1、librsvgなどの開発パッケージが必要です。UI・モデル・Workerは共通ですが、この2 OSの配布パッケージはまだ実機検証していません。

## Production build

```powershell
npm ci
npm run assets
npm run desktop:build
```

通常のWindows/MSVCビルドでは以下を生成します。

- `src-tauri/target/release/kikki-pdf.exe`
- `src-tauri/target/release/bundle/nsis/Kikki PDF_0.4.0_x64-setup.exe`

NSISはユーザー単位でインストールする日本語・英語対応のインストーラーです。OSSのライセンス本文も同梱します。現時点ではコード署名していません。WebView2未導入の環境ではインストーラーがRuntimeの取得を必要とするため、オフラインでインストールするときは事前にRuntimeを用意してください。

Windows以外からのクロスビルドは [Tauri公式のWindows配布手順](https://v2.tauri.app/distribute/windows-installer/)に従い、Clang/LLVM、NSIS、cargo-xwinを用意して実行します。

```sh
rustup target add x86_64-pc-windows-msvc
cargo install cargo-xwin --locked
npm run tauri -- build --runner cargo-xwin --target x86_64-pc-windows-msvc
```

変更履歴は [CHANGELOG.md](CHANGELOG.md) にあります。

このワークスペースで使ったローカルツールの再実行用スクリプトは `scripts/build-windows-local.sh` です。`.tools` は開発環境のみに使い、アプリには含めません。Windows上の継続ビルド設定は `.github/workflows/windows.yml` にあります（ワークフローを作成しただけでGitHubへの送信は行っていません）。

## 基本操作

1. 「開く」、Ctrl+O、PDFのドラッグ＆ドロップ、またはexeへのPDFパス引数で開きます。
2. 左側のサムネイルをクリックして移動。サムネイルをドラッグするとページ順を変更できます。
3. 「ページ管理」で回転・複製・削除・空白ページ・結合・抽出・分割・トリミングを操作します。
4. 「編集」「注釈」でツールを選択し、ページ上をクリックまたはドラッグして配置します。
5. 追加オブジェクトを選び、右パネルで内容・座標・サイズ・色を調整します。ドラッグで移動、右下のハンドルでサイズ変更、Deleteで削除できます。
6. Ctrl+Sで保存、Ctrl+Shift+Sで別名保存。Ctrl+Z / Ctrl+YでUndo/Redo。

ページ範囲は `1-3,5` の形式で、空欄は全ページです。範囲は1始まり、内部モデルは0始まりです。通常の「分割」は指定ページごとに保存先を選びます。「分割ZIP」はまとめて保存できます。

## 0.4.0で追加した操作

- OCR実行後、左の「OCR校正」を開きます。行を選ぶと認識領域が青枠で表示され、右パネルで文字・位置を修正できます。「確認済みにする」、未確認だけの表示、文字による絞り込み、対象ページのOCR削除に対応します。
- OCR一覧は100行ずつ表示し、信頼度はエンジンの推定値を示します。校正文字と確認状態は`.kpdf`に保存できます。通常PDFでは校正文字を透明な検索テキストとして保存します。
- 「ページ管理」→「一括操作」で範囲を指定し、左右90°/180°回転、複製、選択位置の順序反転、削除、アプリ内トリミング解除をまとめて行えます。操作全体を1回のUndoで戻せます。
- 「ページ管理」→「分割ZIP」で範囲と1ファイルあたりのページ数を指定。`part-0001.pdf`から連番で格納し、保存先は1回だけ選びます。Workerで実行し、進捗とキャンセルに対応します。PDFの合計256MBまでです。

## 0.3.0で追加した操作

- 左のクリップアイコン「添付ファイル」で既存の添付を一覧・取り出し。任意のローカルファイルを追加し、名前・説明を編集、削除、Undo/Redoできます。
- 「編集」→「リンク」でページ上に透明なリンク領域を作成。右のプロパティで文書内ページまたはHTTP(S)/mailtoを指定し、移動・サイズ変更できます。
- 「ツール」→「リンク管理」で既存/追加リンクの移動先変更・削除。文書内リンクはページ順変更に追従します。外部URLをアプリ内から実行する機能はありません。
- 既存フォームの複数行・最大文字数・複数選択を読み取って入力UIへ反映。新規作成でもこれらを設定できます。

## 0.2.0で追加した操作

- 「フォーム入力」→「フォームを作成・編集」で入力欄を追加します。作成したテキスト欄・チェック欄などはページ上でも入力できます。
- 左の「しおり」で現在ページに追加。名前・移動先・上下順・階層を編集でき、Undo/Redoできます。
- 左の「コメント」で既存コメントを選び、内容変更・削除を行えます。
- オブジェクトを選んでCtrl+C / X / V / Dでアプリ内コピー・切り取り・貼り付け・複製。矢印キーで1pt、Shift+矢印で10pt移動。右のプロパティに最前面/最背面があります。
- 「ファイル」→「編集プロジェクトを保存」で`.kpdf`を作成。「編集プロジェクトを開く」で再編集します。PDF保存とは別の状態として扱い、プロジェクトを開いた後のPDF保存では原本パスを引き継ぎません。以前のUndo履歴は含めません。
- 「ファイル」→「ページを一括画像出力（ZIP）」で範囲・PNG/JPEG・72〜300dpi・JPEG品質を選べます。「テキストを抽出」はUTF-8です。
- Ctrl+Pは現在ページを初期範囲として印刷設定を開きます。印刷は画像方式で、部数・プリンター・両面設定はWindows側の画面で選びます。

## 互換性と現在の制約

- **通常保存は新しいPDFを組み立てます。** デジタル署名、アクセシビリティ構造タグ、ポートフォリオ、レイヤー、文書レベルのアクションなどの完全保存は未対応です。既存の暗号学的署名の有効性は維持しません。重要な原本は別名保存で保持してください。
- 元のページ上のテキスト・ベクター・画像は通常保存時にページコピーで保持します。オブジェクト編集用のモデル/Undo履歴はPDFに埋め込みません。保存後に開き直した追加文字や図形は元PDFの内容となり、以前の編集オブジェクトとしては選択できません。再編集用には別途`.kpdf`を保存してください。
- **標準AcroFormは再入力可能な状態で保存します。** フォーム画面の「固定して保存」で明示的にflattenすることもできます。フィールド作成は5種類に対応し、位置・サイズ・選択肢・必須・読み取り専用・複数行・最大文字数・複数選択を設定できます。既存フィールドの配置変更とJavaScript計算は未対応です。XFAの保存はエラーで停止します。署名フィールドを含むPDFは通常保存を拒否し、固定保存を選んだ場合も暗号学的署名を保持しません。既存フィールドの値の外観は保存後に更新します。日本語の再入力を可能にするため完全なフォントを埋め込み、出力サイズが増える場合があります。同名フィールドの結合時には名前に連番を付けます。複製した元PDFページのフィールドは同じ値を共有します。
- 既存文字編集は見た目の置換です。元の文字列は検索や抽出で取得され得ます。背景が単色でないページ、特殊な文字組み・縦書き・複雑な回転テキストは正確に置換できません。Word型の段落再レイアウトやContent Stream編集は未実装です。
- Noto Sans JPを同梱し日本語を出力します。欧文標準フォントに日本語を指定すると書き出しエラーになります。日本語の太字・斜体は見た目を合成する方式です。任意のシステムフォントの列挙/埋め込み、自動行折り返し、字詰め・高度な文字組みは未対応です。
- 矩形・円・直線・矢印はページ描画として保存します。蛍光ペン・下線・取り消し線・手描きはそれぞれHighlight / Underline / StrikeOut / Ink注釈、付箋はText注釈として保存します。外観ストリームも生成します。文字選択に連動する注釈範囲指定やコメント返信スレッドの保持は未対応です。画像と手描きによる署名は「デジタル署名」ではありません。
- しおりの移動先はページ単位です。元のズーム・スクロール位置・外部URLのしおりは保持しません。ページ内の通常のGoToリンクは並べ替え後のページへ再接続し、削除された移動先は除きます。HTTP(S)/mailtoリンクは保持します。Launch/JavaScriptなどのアクションや注釈の返信・Popup関連は保存しません。
- 編集プロジェクトは展開後512MBまで、内部JSONは16MBまでです。**元PDFや見た目の置換前の内容を含み、暗号化されません。** 墨消し適用済みPDFの代わりにプロジェクトを共有しないでください。破損検出のハッシュは署名・改ざん認証ではありません。
- 一括画像出力は画像の合計512MBまで、各ページ2000万画素まで。印刷は準備する画像の合計1億2000万画素までです。範囲を分けて大きな文書を処理してください。印刷用データは印刷終了イベントか次の印刷準備時に解放します。
- **トリミングは表示領域の変更だけです。** 元の内容の削除には使用できません。
- **墨消しは品質と機能を引き換えにした画像再構成方式です。** 元のContent Stream・画像・OCR・フォーム・添付・メタデータを出力にコピーしません。出力は検索・選択・リンク・フォームのない画像PDFになります。通常最大180 dpi、巨大ページは画素数制限で低下します。領域外の同じ情報、元ファイル、バックアップ、復旧データの削除は保証しません。保存した出力全体を確認してください。ベクターを保つ選択的な安全な墨消しエンジンは未実装です。
- OCRは最大144 dpiで処理し、誤認識や位置ずれがあり得ます。このアプリで追加した認識文字は「OCR校正」で修正できます。既存PDFに埋め込まれたOCR層の校正、縦書きの最適化、手書き認識専用モデルは未実装です。通常PDFを再び開いた場合は元PDFの文字となるため、校正を続けるには`.kpdf`も保存してください。認識文字を修正しても元のスキャン画像は変化しません。
- 復旧状態と登録署名はWebViewのローカルIndexedDBに保存します。**暗号化PDFを開いた場合も復旧データは平文です。** パスワードそのものは復旧状態・履歴・ログへ保存しません。OSのディスク暗号化を必要に応じて併用してください。
- 保存先の一時ファイルは同じディレクトリに作成し、同期後に置換します。通常終了・通常の失敗では削除しますが、電源断/プロセス強制終了での残留やストレージ上の完全消去は保証しません。
- 300ページの高解像度同時描画はしませんが、元のPDFバイト列と編集モデルはメモリーに保持します。保存Workerには入力がコピーされます。数GB級PDF向けの部分読み込み、ディスクバックドキャッシュ、メモリー上限管理は未実装です。
- Office変換と暗号学的電子署名は `src/security/contracts.ts` に追加プロバイダーの境界を用意しています。変換/署名エンジン自体は含めていません。

添付ファイルは名前ツリー・文書のAF・ページのFileAttachmentを読み取り、通常保存で保持します。同名ファイルには番号を付けます。追加と取り出しは1件128MBまで。ページ抽出・分割には添付を含めません。外部ファイル参照、PDFポートフォリオの分類、ページや構造要素のAF関連は未対応です。添付を削除したPDFでは参照と対応する埋め込みストリームを除きますが、`.kpdf`・Undo・復旧状態には元データが残ります。機密情報を共有する際は最終PDFを確認してください。

リンクの枠は編集画面だけに表示され、PDFには透明なLink注釈を保存します。新規リンクと変更した文書内リンクはページ全体への移動です。既存リンクの位置変更は未対応ですが、削除して新規作成できます。

## アーキテクチャ

```text
React UI → Command → History / DocumentModel → PDF export Worker → native atomic save
               ↑              ↓
          Undo / Redo     local recovery (IndexedDB)

PDF.js Worker: ページ描画、テキスト抽出、検索
Tesseract Worker/WASM: OCR（同梱言語データ）
Rust: ファイル選択・読み書き許可、バイナリIPC、暗号化、原子的置換
```

- `viewer/`: 表示、検索、座標変換、遅延描画
- `editor/`: 操作の調整、選択オブジェクト、既存文字エンジン
- `pages/`, `annotations/`, `attachments/`, `links/`, `forms/`, `ocr/`, `redaction/`: 各機能
- `commands/`: モデル変更、履歴、キャンセル
- `state/`: 中央モデル、外部ストア、復旧保存
- `export/`: pdf-lib処理とWorker境界
- `platform/`, `src-tauri/src/`: ネイティブI/O・暗号化
- `components/`: メニュー、ツールバー、サイドバー、ダイアログ、プロパティ

モデルの座標は元ページのCropBoxを基準にした左上原点のptです。ページ回転は別プロパティで管理し、表示と保存時に変換します。元のバイト列はコマンドで書き換えず共有します。保存したリビジョンを識別し、別名保存した後にUndoしても保存先が原本に戻らないようにしています。

## セキュリティ設計

Tauriの権限はウィンドウタイトル・終了・イベントに限定し、汎用shell/任意コマンド実行APIは公開していません。ファイルアクセスはネイティブの選択/ドロップ/起動引数/最近の文書で許可したパスだけです。別名保存先はネイティブダイアログで選び、一度限りのトークンを発行します。通常保存のデータはバイナリIPCで渡します。CSPはローカル資産とIPCに限定します。PDFのスクリプトや外部リンクを実行する機能は設けていません。

検証環境・実行コマンド・結果は [docs/VALIDATION.md](docs/VALIDATION.md) を参照してください。ビルド成功とWindows画面の起動成功は別々に記録します。テストで使用するPDFはコードから生成したデータで、ユーザーの文書は使用していません。

## アプリ名の変更

`src/config.ts` の `APP_NAME` と `src-tauri/tauri.conf.json` の `productName` / ウィンドウ `title` を変更します。アプリの識別子 `io.kikki.pdf` を変えると既存の設定/復旧データの場所も変わります。実行ファイル名も変更する場合は `src-tauri/Cargo.toml` のpackage名を変更してください。
