# Kikki PDF

Tauri 2 / React / TypeScript / Vite / Rust で作った、ローカル処理のPDF編集デスクトップアプリです。Windows 11を第一対象とし、画面のデザイン・アプリの編集モデル・操作コマンドは独自実装です。PDFの解釈・描画・書き出しにはOSSを使用しています。

**バージョン0.34.1は実際のPDFを開いて編集・保存できる初期実用版です。Acrobat Pro相当の全機能・互換性を達成した完成製品ではありません。** 対応範囲を限定した既存文字の直接編集、墨消し時の画像化など、以下の制約を確認してください。

Windows配布物は [0.34.1インストーラー](artifacts/windows/Kikki.PDF_0.34.1_x64-setup.exe) と [圧縮ZIP](artifacts/windows/Kikki.PDF_0.34.1_x64-setup.zip) です。[チェックサム](artifacts/windows/SHA256SUMS-0.34.1.txt)も同梱します。[GitHub Releases](https://github.com/Superkikki/kikkipdf/releases/tag/v0.34.1)からもダウンロードできます。

## 0.34.1：Word出力のページ範囲指定

Word形式のテキスト出力で、`3,1-2`のようにページ範囲と出力順序を指定できます。空欄なら全ページを出力します。

## 0.34.0：Excel・PowerPointへの書き出し

「ファイル」→「Excel形式で書き出し（テキスト）」で、選択したページの文字をページごとのシートに保存できます。文字は1行ずつA列の文字列セルに入り、`=`で始まる文字も数式として実行されません。元の表の列・数値・数式・画像・書式は再現しません。スキャン画像は先にOCRを実行してください。最大200ページ・合計1000万文字・1ページ5万行・1行32767文字までです。

「ファイル」→「PowerPoint形式で書き出し（画像）」で、選択ページを1ページずつスライド画像にできます。見た目を保持しやすい一方、文字や図形を個別に編集することはできません。画像は144dpiを基準に最大2000万画素、JPEG品質90%。スライドの縦横比は最初のページを基準にし、比率が異なるページは中央に配置します。最大100ページ・画像合計48MiBまでです。どちらもページ範囲を指定でき、Officeのインストールは不要です。

## 0.33.0：Office変換

「ファイル」→「OfficeからPDFを作成」で、Word（.docx）、Excel（.xlsx）、PowerPoint（.pptx）をPDFに変換して開けます。Windows版と、対応するMicrosoft Officeデスクトップアプリのインストール・ライセンス・初回設定が必要です。Officeに他の文書が開いている場合は閉じてから実行してください。入力は32MiBまで、変換結果は128MiBまでです。元ファイルのコピーを一時フォルダーに置いて読み込み、元ファイルを上書きしません。変換後のPDFは保存先を選んで保存します。

マクロを無効化し、WordとExcelのリンク更新を抑止します。Officeの外部リンク・データ接続などによっては、Office自身がネットワークにアクセスする可能性があるため、変換前に文書の内容を確認してください。リンク先が相対パスの場合は一時フォルダーを基準に解決されるため、元の内容を再現できないことがあります。キャンセル後もOffice側の処理が続く場合があります。Officeの変換機能によるレイアウトの差、ライセンスや初回設定の画面が出る場合があります。

「ファイル」→「Word形式で書き出し（テキスト）」では、選択したページの編集内容から文字を抽出し、ページ区切り付きの編集可能な.docxとして保存します。こちらはOfficeのインストール不要です。画像・表の構造・書式・元のレイアウトは再現せず、PDFのテキスト抽出順に依存します。スキャン画像の文字は先にOCRを実行してください。選択範囲は2000ページ・合計1000万文字まで。Excel・PowerPointへのテキスト／画像出力は0.34.0から対応します。

## 0.32.1：20MB以下のWindowsインストーラー

インストーラーを23.13MBから**15.85MB（15,853,075 bytes）**に削減しました。ZIPも15.81MBです（MBは1,000,000 bytes）。未使用の旧方式OCRエンジンと重複したWASMを配布対象から外し、日本語・英語のオフラインOCR、SIMD対応／非対応の両エンジン、編集機能を保持しています。

## 0.32.0：既存Type 3フォントの直接編集

既存PDFに埋め込まれたType 3フォントの文字を、対応条件を満たす場合に直接編集できます。字形名またはToUnicodeからUnicodeを確認し、文字幅と字形描画命令の幅が一致することを検証します。編集した元の文字描画を取り除き、後続文字の位置を保持して置換文字を追加します。Undo／Redo、PDF・編集プロジェクト保存にも対応します。

対象は標準の `FontMatrix [0.001 0 0 0.001 0 0]`、対応するEncoding・Widths・CharProcsを持ち、各字形の先頭の `d0`／`d1` に記載された幅が一致する横書き文字です。Unicode、字形データ、幅を検証できない文字や特殊な変換行列は対象外です。元の書体の字形を再現するのではなく、選択したフォントで置換文字を描きます。Windowsでは隣の文字と選択領域が重なる場合があり、その際は対象文字の左側をクリックしてください。

## 0.31.0：日本語と数字の文字抽出、ベイツ番号の日本語対応

追加した横書きテキストをPDFへ保存する際、日本語と数字が混在すると数字が検索・文字抽出で別の文字になる問題を修正しました。日本語・登録フォントについて、実際に使用した字形の幅とUnicodeの対応を保存します。字形が同じで異なる文字に対応するなど、正しい対応を確定できない場合は保存を中止し、理由を表示します。既存のPDFに書き込まれた誤った文字対応を修復する機能ではありません。

「ページ管理」→「ベイツ番号」の接頭辞・接尾辞に日本語を使えるようになりました。英数字のみの場合は標準欧文フォント、日本語を含む場合は日本語フォントを使用します。番号のプレビュー、6つの配置、Undo／RedoとPDF・プロジェクト保存に対応します。

## 0.30.0：ベイツ番号の追加

「ページ管理」→「ベイツ番号」で、指定ページに管理用の連番を印字できます。接頭辞・接尾辞（半角英数字と記号、各64文字以内）、開始番号、番号の桁数、配置、余白、文字サイズと色を設定します。ページ範囲は `1-3,5` の形式で指定し、空欄なら全ページです。選択したページの順に連続番号を割り当てます。桁数が不足する場合やページの表示領域が小さすぎる場合は追加せず、理由を表示します。

印字する番号をプレビューしてから一括追加します。ページの回転・トリミング後の表示面を基準に配置し、Undo／RedoとPDF・編集プロジェクト保存に対応します。追加した番号はテキストとして個別に編集できます。適用後にページを並べ替えても番号は自動で変わりません。長い番号はページ幅からはみ出す場合がありますので、保存したPDFを確認してください。現時点では複数のPDFをまたいだ連番付けは対象外です。

## 0.29.0：PDF圧縮・複数PDFの一括処理・フォーム枠の自動検出

「ファイル」→「PDF圧縮・最適化」で、現在の編集内容を別のPDFとして圧縮できます。画質維持の構造最適化、JPEG品質82%・長辺2000pxまで、JPEG品質65%・長辺1200pxまでの3設定に対応。文字・図形・フォームをページ画像へ変換せず、8bit RGB／グレーの対応画像だけを再圧縮します。透明・CMYK・特殊な色変換・予測フィルター付き画像などは保持します。通常保存したPDFとのサイズ比較、削減率、処理した画像数を表示し、大きくなる場合は通常保存したデータを採用します。比較対象は読み込み元のPDFではありません。編集内容やフォントの追加により、元ファイルより大きくなる場合があります。

「ファイル」→「複数PDFを一括処理」は文書を開く前から使えます。圧縮・全ページの回転・文書情報（Infoと文書レベルXMP）の削除を組み合わせ、成功したPDFと処理結果のreport.jsonをZIPで保存します。同名には連番を付け、不正なPDFは理由を表示して他のPDFの処理を続けます。元ファイル・編集中の文書は変更しません。キャンセル時はZIPを保存せず、再実行できます。50件、1件32MB、入力／出力の合計256MBまで。署名欄・電子署名付きPDFは拒否し、暗号化PDFは先に復号してください。文書情報の削除は注釈・添付・ページ内の個人情報を削除する機能ではありません。

「ツール」→「フォーム入力」→「入力枠を自動検出」で、現在のページの空の長方形と小さい正方形を検出します。スキャン画像・回転・トリミング済みのページにも対応。プレビューで候補を選別し、項目名・文字入力／チェック欄の種類を変更してから、最大200件をまとめて追加できます。既存欄との重なりを除外し、追加全体をUndo／Redoできます。PDF・編集プロジェクト保存に対応。枠のない欄、記入済み・傾いた枠、項目の意味や名前の自動判定は対象外です。検出後は候補を確認し、必要に応じて作成・編集画面で配置を調整してください。

## 0.28.0：ページ順序の一括編集と表裏スキャンの交互配置

「ページ管理」→「ページ順序」、または「ページ」メニュー→「ページ順序を編集」で、全ページの順序を番号で指定できます。例として6ページなら `3-1,4-6` で3・2・1・4・5・6の順にします。逆向きの範囲にも対応し、重複・抜け・範囲外がある指定は適用しません。番号は画面を開いた時点の物理ページ番号です。

「全体を逆順」「奇数ページ→偶数ページ」「偶数ページ→奇数ページ」「前半と後半を交互に並べる」も選べます。表面PDFの後ろに裏面PDFを追加した後、前半のページ数を指定して表裏を交互にできます。裏面を逆順にスキャンした場合は「後半を逆順にする」を使います。6ページを3枚ずつに分ける初期設定では、1・6・2・5・3・4の順です。前半と後半の枚数が違う場合は、余ったページを最後へ並べます。生成した順序は手動指定へ移して調整できます。

適用前に変更後の位置・現在のページ番号・ラベルをプレビューし、12件を超える場合は先頭6件と末尾6件を表示します。10000ページまで。ページのID・編集内容・ラベルと、しおり・リンク・フォームの参照を保持し、Undo／RedoとPDF・編集プロジェクト保存に対応します。順序が同じ場合は履歴を追加しません。画面を開いた後に文書が変わった場合は、開き直して確認してください。

## 0.27.0：添付の検索・ZIP一括取り出し・削除と復元

「添付」で名前・説明を検索できます。全角／半角・英字の大小を同一視し、「現在の添付」と「削除した添付」を切り替えられます。一覧は100件ずつ追加表示します。

「絞り込んだ添付をZIPで取り出す」は、元PDFの添付と追加した添付をまとめて保存します。変更後の名前を使い、パスやWindowsで使えない名前を整え、大小文字だけの違いを含む同名には番号を付けます。画面の次ページも含む絞り込み結果全体が対象です。Workerで処理し、進行表示・キャンセルに対応。1000件・1件128MB・展開後合計とZIP自体が256MBまでで、取り出しはPDFや編集状態を変更しません。

一括削除・一括復元は確認後にまとめて実行し、Undo／Redo・PDF・編集プロジェクト保存に対応します。「削除した添付」では1件ずつの復元もできます。変更した名前・説明・元データは復元時に保持します。処理や確認の途中で文書が変わった場合は一括変更・ZIP保存を中止します。復元は元データが残る編集中または編集プロジェクト内で可能です。削除したPDFを開き直した場合、除去済みの添付をそこから復元することはできません。

## 0.26.0：しおりJSONの入出力と検索結果の一括削除

「しおり」→「しおりの入出力・一括削除」で、全件をJSONに書き出して別のPDFへ読み込めます。階層・ページ内の表示位置／倍率・URL・文字色・太字・斜体・折りたたみを保持します。読み込みは既存しおりの後ろへ追加し、各項目に新しいIDを付けます。「ページ番号の補正」に1を指定すると、JSON内の2ページ目は現在の文書の3ページ目に移ります。ページは表示ラベルではなく1始まりの物理ページ番号、位置・倍率は同じPDF座標です。書き出しは検索条件にかかわらず全件で、文書の保存状態・Undo履歴を変更しません。

しおり名の検索結果を子階層ごと一括削除できます。全角／半角・英字の大小を同一視し、名前の一致件数と子を含む削除総数を確認します。検索欄が空なら全件が対象です。削除後はUndo／Redoで戻せます。

入出力・一括削除は合計10000件・24階層まで、JSONはUTF-8・8MBまでです。不正なJSON・URL・参照先・過大な階層、補正後の範囲外ページは全件を中止します。確認中に文書が変わった場合も変更しません。追加・削除はPDF・編集プロジェクト保存に対応。外部URLは自動で開かず、PDFや元ファイルのパス・内部IDはJSONに含めません。

登録フォントの文字組みが完了してから日本語入力を確定した際、保存が進まなくなる場合も修正しました。

## 0.25.0：レイヤーの順序・見出し階層としおり複製

「レイヤー」→「レイヤーの順序・階層を編集」で、名前付き見出しの作成・改名・解除、項目の上下移動と見出しへの移動ができます。見出しだけの削除は中の項目を一つ外側へ戻します。「元の順序・階層に戻す」で元PDFの構造へ戻せます。表示状態・ロック・排他設定は保持し、Undo／Redo、PDF・編集プロジェクト保存、ページ抽出・結合に対応します。12階層・合計20000項目まで。レイヤー自体の新規作成、レイヤーを親にする特殊な階層の編集は対象外です。編集できない元構造は理由を表示し、保存時に保持します。

「しおり」で対象を選び「しおりと子のしおりを複製」を押すと、直後へ子階層ごと複製します。移動先ページ・表示位置・倍率・外部URL・文字色・太字・斜体・折りたたみ状態を保持し、複製後は個別に編集できます。Undo／RedoとPDF・編集プロジェクト保存に対応。複製後の合計10000件・24階層までです。

## 0.24.0：回転・反転された既存画像とコメントの一括操作

90度・180度・270度の回転、水平・垂直反転、回転と反転を組み合わせて配置された既存画像を直接編集できます。「ツール」→「既存画像」で選び、元の向きを保って移動・サイズ変更・差し替え・削除できます。同じ画像を使う別の箇所を保持し、Undo／Redo・PDF・編集プロジェクト保存に対応します。元の画像をそのまま使う移動・サイズ変更では画像データを再圧縮しません。取り出し・独立したコピーには元の画像データを使用します。

対応するForm内の画像も対象です。FormのBBoxを超える編集、傾斜、90度単位以外の回転、明示的クリッピング、透明グループなどは引き続き対象外です。

コメントパネルの「絞り込み結果を一括変更」で、次の操作ができます。

- 「メモ注釈○件を一括レビュー」：メモ注釈（Text）のレビュー状態をまとめて設定します。
- 「作成者を一括変更」：既存・追加・取り込みコメントの作成者を変更します。空欄で作成者を解除します。
- 「絞り込み結果を一括削除」：対象件数を確認してから削除します。

検索・作成者・状態・ページ・種類で絞り込んだ結果が対象です。編集可能なコメントだけを数え、一覧の次ページも含めて最大5000件を一括操作します。Undo／Redoは全件を1回で戻せ、PDF・編集プロジェクト保存にも反映します。変更がない場合は履歴を追加しません。確認画面を開いている間に文書が変更された場合は、全件を変更せず中止します。

## 0.23.0：検索結果の保存とレイヤーの一括操作

検索パネルの「検索ページ範囲」で、`1-3,5`のように対象ページを指定できます。空欄は全ページです。指定の重複はまとめ、文書のページ順に検索します。範囲外や不正な入力では検索結果を表示せず、入力を修正すると再検索します。検索は文書の編集履歴・保存状態を変更しません。

「検索結果をCSV保存」で、一覧の表示ページにかかわらず現在の全検索結果を保存できます。UTF-8 BOM付きで、ページ番号・前後の文脈・一致文字・検索語・ページ範囲・検索条件を記録します。検索結果の上限は5000件で、上限により省略がある場合はCSVにも記録します。検索中や結果がない場合は保存できません。

レイヤーパネルに「すべて表示」「すべて非表示」「表示を反転」を追加しました。元PDFごとにロックされていないレイヤーを一括変更し、ロック中の表示と他の元PDFは保持します。排他グループの複数レイヤーが表示される場合は、全件を変更せず案内を表示します。一括Undo／Redo・PDF・編集プロジェクト保存に対応し、変更がない場合は履歴を追加しません。

## 0.23.0：直接編集できる既存フォントの拡大

日本語のShift-JIS（90ms-RKSJなど）・EUC・UniJISなど、PDF.jsに同梱する標準CMapを使う複合フォントを直接編集できます。中国語のGB・Big5系、韓国語のUHC系にも対応します。ToUnicodeがない場合も、Adobe-Japan1／GB1／CNS1／Korea1のCIDコレクションから文字を確認できれば対象にします。Identity-H／Vもこの対応を利用でき、縦書きは従来と同じ原点・幅の確認条件で扱います。

PDF内に埋め込まれたEncoding CMapのcodespacerange・cidchar・cidrangeと、標準CMapの継承にも対応します。1〜4バイトの文字コードを解釈し、Unicodeは元のToUnicodeを優先し、文字幅は変換後のCIDに対応する元のW／DWを使います。CMapは同梱のローカル資産を利用します。

欧文では、FontDescriptorが付いた未埋め込みの標準14書体、既定の文字対応と元の幅を確認できるType1・MMType1・TrueTypeも対象を広げました。未対応のフォントには、確認できなかったフォント名と理由を表示します。

保存時には元の文字描画を除去し、後続文字の位置を保持して新しい文字を描画します。置換には選択したフォントを使うため、元の書体の完全な再現や段落の自動再レイアウトは保証しません。Unicodeや元の幅を確認できないフォント、未対応のCMap継承などは対象外です。Type 3は0.32.0から検証できる範囲で対応します。この変更は0.23.0インストーラーに含めています。

起動時のGHOST PROTOCOL演出も同梱しています。EscまたはSKIP INTROですぐに閉じられ、Ctrl+Shift+Kで再生できます。詳細は[起動演出](docs/ghost-protocol.md)を参照してください。

## 0.22.0：既存文字の直接編集の対応拡大

色空間を明示する `cs`／`CS` と `sc`／`SC`／`scn`／`SCN` によるDeviceGray・DeviceRGB・DeviceCMYKの文字色指定に対応しました。ColorSpaceリソースのデバイス色空間への別名参照、塗りと輪郭線の別々の色指定、`q`／`Q`による色空間の復元も扱います。パターン・ICC・特色など未対応の色空間は対象外です。

`re`で作られた矩形に加え、`m`／`l`で4辺を結んだ矩形クリップ内の文字を編集できます。明示・暗黙の閉路と90度単位の座標変換に対応し、文字全体が矩形内に収まる場合に限ります。複数の部分パス・曲線・矩形以外・文字が欠けるクリップは対象外です。

均等倍率の回転を含む座標変換内の横書きの輪郭線付き文字にも対応しました。元の輪郭線の色・太さ・塗りの有無と最初のベースラインを引き継ぎ、後続文字の位置を保って元の文字描画を除去します。輪郭線を変形する不均等倍率・せん断・反転は対象外です。編集プロジェクトとPDF保存に対応します。0.22.0のWindows配布物に含めています。

## 0.21.0：PDF比較の文字差分

「ツール」→「PDF比較」で「文字差分も比較する」をオンにすると、画像の比較に加えて抽出文字を比較します。現在の文書と比較対象を左右に並べ、比較対象側で削除された文字を赤、追加された文字を緑で表示し、それぞれの文字数を示します。未保存の文字編集・フォーム固定保存の文字を反映し、抽出可能な不可視文字の変更もページ一覧の「変更あり」に含めます。比較は編集履歴・保存状態を変更しません。

PDF.jsが抽出した順序の文字列を比較します。空白・改行の違いも検出しますが、段組みの読み順やPDFの作り方により見た目が同じでも差分が出る場合があります。画像の文字認識・意味の比較・途中に挿入されたページの自動対応は行いません。文字が抽出されないスキャンPDFでは画像比較を使います。

上限は各ページ・各文書側20,000文字、両文書合計1,000,000文字（上限はUTF-16コード単位）です。上限を超えた場合は結果を部分表示せず中止し、文字比較をオフにして画像比較を再実行できます。大きな文字変更は共通の先頭・末尾を除いた範囲をまとめて表示し、その範囲の文字数を数えます。通常の追加・削除件数はUnicodeコードポイント単位です。

JSONレポートは文字比較の有無、ページごとの文字差分・追加削除数・簡略表示の有無を記録します。文字比較をオンにすると変更のない文字も含め抽出本文を記録します。0.21.0のWindows配布物に含めています。

## 0.21.0：レイヤー表示プリセットの作成・編集

「レイヤー」→「現在の表示をプリセットに保存」で、元PDFごとの全レイヤーの表示状態を名前付きで保存できます。作成したプリセットを選び「選択プリセットを上書き」で現在の表示と名前に更新し、「選択プリセットを削除」で削除できます。作成・上書き・削除はUndo／RedoとPDF・`.kpdf`保存に対応します。元PDFから読み込んだプリセットは保持し、上書き・削除の対象にしません。PDF保存後に開き直すと、作成した設定も元PDFのプリセットとして読み込みます。

適用時はロック・排他設定を検証し、競合した場合は全件を中止します。元のプリセットを含め100件・合計10万レイヤー参照まで。結合時も作成したプリセットを保持し、他の元PDFの表示状態を変更しません。元PDFの代替設定の統合は未対応です。名前付き見出しによる階層編集は0.25.0から対応します。0.21.0のWindows配布物に含めています。

### フォームの編集・既定値操作

「ツール」→「フォーム入力」→「フォームを作成・編集」で既存の入力欄を選び、「項目を全ページから削除」「削除した項目を復元」「独立した項目として複製」を使えます。削除は同じ項目の全ページの入力欄に反映し、入力画面・XFDF出力・保存PDFから除きます。削除済みの項目は一覧から選び直して復元できます。値・設定・配置は保持し、Undo／Redoと`.kpdf`保存にも対応します。

複製は選んだページに独立した追加項目を作ります。5種類の欄の現在値・既定値・必須・読み取り専用・複数行・文字数制限・選択肢・複数選択を引き継ぎ、名前に`_copy`などの連番を付けます。選択欄の表示名と保存値も保持し、複製後に別々に編集できます。ラジオはグループ全体を縦に並べた追加項目として作成します。元の独自外観・PDF本文のラベル・レイヤー条件は複製せず、このアプリの外観を生成します。不正な入力値・既定値がある欄は複製を中止します。

項目の削除は墨消しとは別の操作です。元PDF・編集プロジェクト・Undo履歴・復旧データには元の項目と値が残ります。

「ツール」→「フォーム入力」→「値を入力」に「入力値をPDFの既定値に戻す」を追加しました。元PDFのDV（親フィールドからの継承を含む）を読み取り、テキスト・チェックボックス・ラジオボタン・ドロップダウン・リストを一括で戻します。「入力値を読み込み時に戻す」とは異なる操作です。DVのない欄は空にします。追加した欄も、既定値を設定していればその値へ戻します。

読み取り専用欄・設定・配置を保持し、1回のUndo／RedoとPDF・`.kpdf`保存に対応します。ラジオボタンの保存値を改名した場合は、元と同じ選択位置へ戻します。現在の選択肢・複数選択・文字数制限に合わない既定値や不正なDVがある場合は、全件を変更せず中止します。変更がない場合は履歴を追加しません。PDF内のResetFormアクションやスクリプトは実行しません。

「現在の入力値を既定値に設定」で、表示中の文書の既存欄・追加欄の現在値を一括でDVに設定できます。「既定値を解除」は継承されたDVも含めて解除します。どちらも現在の入力値と読み取り専用欄を保持し、1回のUndo／RedoとPDF・`.kpdf`保存に対応します。選択欄は表示名ではなく保存値を記録します。不正な入力値がある場合は全件を中止し、同じ操作を繰り返して変更がなければ履歴を追加しません。

編集した既定値に合わない選択肢・文字数制限への変更は拒否します。先に既定値を解除するか、入力値を修正して既定値を設定し直してください。既存欄の「元の設定に戻す」は、編集した既定値も元PDFの設定へ戻します。

DVの意味は[Adobe PDF ReferenceのReset-Form Actions](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.4.pdf)に基づきます。このアプリではDVのない欄を空の入力値として保存します。

## 基本操作

1. 「開く」、Ctrl+O、PDFのドラッグ＆ドロップ、またはexeへのPDFパス引数で開きます。
2. 左側のサムネイルをクリックして移動。サムネイルをドラッグするとページ順を変更できます。挿入線の位置に移動し、Alt＋↑／↓でも前後へ移動できます。
3. 「ページ管理」で回転・複製・削除・空白ページ・結合・抽出・分割・トリミングを操作します。
4. 「編集」「注釈」でツールを選択し、ページ上をクリックまたはドラッグして配置します。
5. 追加オブジェクトを選び、右パネルで内容・座標・サイズ・色を調整します。ドラッグで移動、右下のハンドルでサイズ変更、右クリック→「削除」またはDeleteで削除できます。右クリックの削除は、矩形・円・線・テキスト・画像・注釈に共通です。描画ツールの選択中も使え、Ctrl+Zで元に戻せます。
6. Ctrl+Sで保存、Ctrl+Shift+Sで別名保存。Ctrl+Z / Ctrl+YでUndo/Redo。

ページ範囲は `1-3,5` の形式で、空欄は全ページです。範囲は1始まり、内部モデルは0始まりです。通常の「分割」は指定ページごとに保存先を選びます。「分割ZIP」はまとめて保存できます。

## クリックして文字を編集（0.14.0）

- 「選択」ツールでPDFの本文や追加した文字を1回クリックすると、クリック位置にカーソルを置いてページ上で入力できます。「テキスト」で追加した直後も入力欄へフォーカスし、初期の文字をそのまま書き換えられます。追加文字はTabで選び、Enter／F2でも編集できます。
- Enterまたはチェックボタンで確定、Shift＋Enterで改行、Escまたは取消ボタンで編集中の変更を取り消します。日本語の変換中に押すEnter／Escでは編集を終了しません。外側クリック、別ページへのスクロール、Ctrl＋Sでも入力を確定します。入力中のCtrl＋Z／Yは入力欄のUndo／Redo、入力欄を離れると文書のUndo／Redoです。
- 文字が増えた場合は編集領域を広げます。縦書きは右端を保って左へ広げます。欧文の標準フォントへ日本語を入力した場合はNoto Sans JPへ切り替えます。登録フォントは保持し、含まれない文字は編集欄で警告します。フォントの確認中・エラー時やIME変換中は保存・印刷・文書切替を止め、入力内容を保持します。訂正して確定するか、Escで取り消してから続行してください。
- 元の本文はドラッグで選択・コピーでき、追加文字はドラッグで移動、右下のハンドルでサイズを変更できます。フォント・色・揃えなどは引き続き右のプロパティから調整できます。
- 直接編集できるPDF形式の範囲は以下の互換性欄のとおりです。未対応の文字は案内を表示し、「ツール」→「見た目の置換」を選ぶと背景マスク方式で編集できます。
- クリック編集と既存フォントへの対応拡張は0.14.0のWindowsインストーラーに含めています。

## コメントの検索とレビュー

サイドバーの「コメント」で、内容・作成者を検索し、作成者・状態・ページで絞り込めます。全角半角・大文字小文字を揃えて照合し、一覧は100件ずつ表示します。空のメモと標準のマークアップ注釈も一覧に含めます。選択するとページへ移動し、内容・作成者を編集できます。

メモ注釈（Text）は未確認・承認・却下・取消・完了のレビュー状態を設定できます。変更・削除はUndo／RedoとPDF・`.kpdf`保存に対応します。その他のマークアップでは内容・作成者の編集に対応し、レビュー状態は設定しません。返信スレッドと共有レビューは未対応です。XFDFの書き出し・読み込みは下記の手順に対応します。

## コメントをXFDFへ書き出す（0.15.0）

- 左の「コメント」から「全件をXFDF保存」または「絞り込み結果をXFDF保存」を選びます。100件ごとの一覧表示に関係なく対象全件を出力します。現在の内容・作成者・メモのレビュー状態を反映し、削除済みコメントは含めません。
- メモ（Text）、蛍光ペン（Highlight）、下線（Underline）、取り消し線（StrikeOut）、手描き（Ink）が対象です。追加したマークアップもコメント一覧で内容・作成者を編集できます。既存のFreeText・Stampなど対象外の種類を含む場合は保存を止め、対象外の種類を表示します。「種類」→「XFDF対応の種類」で対象だけへ絞り込んでから保存できます。内容・作成者・ページの条件と組み合わせられます。
- UTF-8のXMLとして位置・色・透明度・本文・作成者を出力し、ページ番号は現在の文書順で0始まりです。CMYKの色はRGBへ近似変換します。PDF本体は含みません。同じページ構成・座標を持つPDFと一緒に扱ってください。ページを複製した場合も別の注釈として識別します。
- 返信関係・添付・外観ストリームの完全な移行は未対応です。Acrobat等の他製品への読み込み互換性は実機で未検証です。コメント出力は文書の保存状態・Undo履歴を変更しません。

## XFDFコメントの読み込み（0.16.0）

- コメントパネルの「XFDFを読み込む」を選んでファイルを指定します。読み込んだ注釈は既存注釈を置き換えず、新しいIDで追加します。ファイル全体が1回のUndo操作となり、Undo／RedoとPDF・`.kpdf`保存に対応します。元PDFの内容を破壊せず、注釈として追加します。
- メモ（Text）、蛍光ペン（Highlight）、下線（Underline）、取り消し線（StrikeOut）、手描き（Ink）の5種類に対応します。ハイライト等の複数QuadPointsと手描きの複数ストロークを保持し、ページのCropBoxと回転を考慮して位置を変換します。
- UTF-8、またはBOM付きUTF-16（LE／BE）のXMLを読み込みます。ファイルは8 MB以下、注釈は1〜5000件、座標点は合計100,000点までです。ページ番号は0始まりで、現在開いている文書のページ順を指します。XFDFの`<f href>`は参照情報として扱い、自動でファイルやURLを開きません。
- 対応外の注釈種類、返信関係、フォーム値、DTD／外部エンティティ、リッチテキストを含むファイルは全体を中止し、一部だけを読み込むことはありません。
- 注釈の外観は本アプリで生成し、メモは共通のアイコンで表示します。独自の外観やpopupの移行は未対応です。`nozoom`／`norotate`フラグは保存しますが、読み込み直後の画面プレビューはページと一緒に拡大・回転します。他製品との実機相互運用は未検証です。

## レイヤー表示

サイドバーの「レイヤー」で元PDFごとのレイヤー名・階層・表示状態を確認し、チェックで表示を切り替えます。ページとサムネイルを再描画し、レイヤーに属するページ上のフォーム入力欄も表示条件に従います。フォーム管理画面では非表示レイヤーの項目も扱えます。ロックされたレイヤーは変更できず、排他グループでは同時に表示するレイヤーを切り替えます。変更はUndo／Redoに対応し、「初期表示に戻す」でその元PDFを開いたときの状態へ戻せます。

名称変更は0.17.0からレイヤー一覧の「名称変更」で行え、Undo/RedoとPDF・編集プロジェクト保存に対応します。表示状態はPDF保存・抽出・結合と`.kpdf`保存・復旧に反映します。元PDFのバイト列は変更しません。保存時は既定のON／OFFと表示用Usageを更新し、印刷用Usageは保持します。代替表示設定の表示状態は0.19.0からプリセットとして適用できます。表示プリセットの作成・編集は0.21.0から対応します。レイヤー自体の作成は未対応です。名前付き見出しによる階層編集は0.25.0から対応します。検索・文字抽出には非表示レイヤーの文字も含まれます。0.12.0のWindows配布パッケージに含めています。

## ページラベル

- 「ページ管理」→「ページラベル」でページ範囲、番号形式、接頭辞、開始番号を設定します。変更予定を確認して「ラベルを適用」を押します。前付けは`i, ii, iii`、本文は`1, 2, 3`、付録は`付録-A, 付録-B`などにできます。「番号なし」では「表紙」などの接頭辞だけを表示します。
- 数字、大文字／小文字のローマ数字、英字に対応します。英字はPDFの方式で`A…Z, AA, BB…ZZ, AAA…`と増えます。開始番号は1〜1000000、ローマ数字は3999まで。接頭辞は128文字、ラベル全体は512文字までです。
- サムネイルとページ見出しにラベルを表示し、通常のページ番号と異なる場合は文書内の位置も併記します。長いラベルは省略表示し、マウスを重ねると全文を表示します。下部の「ラベル」欄に入力してEnterを押すと移動します。照合は大文字／小文字を区別し、同じラベルが複数ある場合は現在ページが一致すればそのまま、それ以外は先頭の一致へ移動します。
- 下部の通常の「ページ番号」、ページ範囲、印刷・抽出などの範囲指定は文書内の1始まりの位置です。ページラベルは印刷される番号や本文を書き換えません。印刷される番号を追加する場合は「ページ装飾」を使用します。
- 元PDFの対応するページラベルを読み込み、通常のPDF保存と`.kpdf`保存に保持します。設定・解除はUndo／Redoに対応し、並べ替え・複製・結合・抽出・分割でもページごとのラベルを引き継ぎます。並べ替え後に自動で番号を振り直すことはなく、必要な範囲へ再設定します。
- PDFへの出力は表示ラベルを明示する方式です。元の番号範囲の定義方式は保持しません。512文字を超えるラベルや制御文字を含むラベル、不正な番号ツリーは読み込み時に通常の番号へ戻します。墨消しの画像再構成ではページラベルもコピーしません。
- この機能は0.12.0のインストーラーに含まれます。

## 文書内検索改善

- Ctrl+Fで検索欄を開きます。元PDFの一致する文字を黄色、現在の結果をオレンジで強調します。追加文字・直接編集・見た目の置換・OCRはオブジェクトの領域を強調します。検索結果を選ぶかEnter／Shift+Enterを押すと、そのページ内の該当位置へ移動します。
- 大文字／小文字の区別、単語全体との一致、全角／半角の同一視を切り替えられます。全角／半角の同一視は既定で有効で、Unicode互換正規化を使用します。単語全体は前後の文字・数字・結合文字・アンダースコアを境界として判定します。日本語の形態素解析や正規表現検索は行いません。
- PDF内で分割された文字片をつないで検索し、改行や連続する空白は1つの空白として照合します。元の文字列・表示位置を保持して強調します。既存コメントの本文は文書内検索に含めません。
- 一覧は100件ずつ、最大5000件です。上限を超える場合は検索語を絞り込む案内を表示します。文字抽出結果を上限付きで再利用し、文書変更・Undo／Redoで検索結果を更新します。
- サイドバーのタブを切り替えても検索語と結果を保持します。「検索をクリア」か検索欄のEscで強調を解除します。検索はPDFやUndo履歴を変更せず、保存PDFにも強調を追加しません。
- この改善は0.12.0のインストーラーに含まれます。

## 互換性と現在の制約

- **通常保存は新しいPDFを組み立てます。** デジタル署名、アクセシビリティ構造タグ、ポートフォリオ、文書レベルのアクションなどの完全保存は未対応です。既存の暗号学的署名の有効性は維持しません。重要な原本は別名保存で保持してください。
- **標準PDFレイヤーを保持して保存します。** 元PDFのOCG・OCMD参照と文書のOCPropertiesを同じ参照でコピーし、初期表示状態、階層、ロック、排他グループ、表示・印刷用Usage／AS設定を保持します。ページの並べ替え・複製・抽出でも維持し、出力ページがない元文書のレイヤー設定は含めません。結合では各元文書の初期表示状態を統合し、同名レイヤーも別グループとして扱います。レイヤーを含む元文書が1件なら代替表示設定（Configs）も保持し、複数件なら元の代替設定は引き継ぎません。0.21.0では本アプリで作成したプリセットを結合時も保持し、対象外の元PDFの表示を保持します。抽出した元文書に属する未使用レイヤーの定義は残ります。レイヤー自体の作成・特殊な階層の編集、非標準の拡張情報、フォーム固定時のレイヤー再現は未対応です。墨消し・画像出力・印刷の画像化ではレイヤー構造を保持しません。異常な参照や過度に複雑な設定は保存を停止します。この変更は0.12.0のWindows配布パッケージに含めています。
- 元のページ上のテキスト・ベクター・画像は通常保存時にページコピーで保持します。オブジェクト編集用のモデル/Undo履歴はPDFに埋め込みません。保存後に開き直した追加文字や図形は元PDFの内容となり、以前の編集オブジェクトとしては選択できません。再編集用には別途`.kpdf`を保存してください。
- **標準AcroFormは再入力可能な状態で保存します。** フォーム画面の「固定して保存」で明示的にflattenすることもできます。フィールド作成は5種類に対応し、位置・サイズ・選択肢・必須・読み取り専用・複数行・最大文字数・複数選択を設定できます。既存欄の移動・サイズ変更にも対応し、0.9.0では上記の設定編集も可能です。既存項目の種類変更、別ページへの配置変更、JavaScript計算は未対応です。ラジオの保存値は現在と同じ件数で変更できます。既存ラジオグループ内の入力欄の追加・削除は未対応です。項目全体の削除・復元と独立項目としての複製は0.20.0から対応します。表示名と保存値が異なる選択欄は、画面に表示名を出し、PDFへ保存値を記録します。既存欄の画面表示は入力用の簡易表示で、装飾・欄自体の回転・特殊な文字組みを完全には再現しません。XFAの保存はエラーで停止します。署名フィールドを含むPDFは通常保存を拒否し、固定保存を選んだ場合も暗号学的署名を保持しません。既存フィールドの値の外観は保存後に更新します。日本語の再入力を可能にするため完全なフォントを埋め込み、出力サイズが増える場合があります。同名フィールドの結合時には名前に連番を付けます。複製した元PDFページのフィールドは同じ値を共有します。
- **直接編集はページ直下と対応するForm XObject内の横書き・対応する縦書きの塗り文字と、対応する横書きの輪郭線付き文字が対象です。** Type1/TrueTypeのWinAnsi・MacRoman・MacExpert・標準エンコーディング、Identity-H／Identity-V＋ToUnicodeのType0/CIDフォントに対応します。0.9.1ではToUnicodeの文字対応表と元のWidthsを検証できる独自エンコーディング（Encoding Differencesなど）・標準エンコーディングの非ASCII文字も編集できます。0.14.0では、ToUnicodeがなくてもAdobeの文字名（`Aacute`・`uni65E5`など）で対応を確認できる独自エンコーディング、日本語・アクセント付き欧文・合字を扱えます。未埋め込みの標準Symbol・ZapfDingbatsの記号にも対応します。元のWidthsまたは標準14書体の元の文字幅を使用し、未知の文字対応や幅は拒否します。0.9.2ではForm XObjectの入れ子・座標変換・リソースをたどり、編集した呼び出しだけを複製して保存します。同じ部品を使う別の箇所やページは保持します。対象はBBox内の横書き・対応する縦書き文字で、90度単位で回転した部品も対応し、外部参照・透明グループ・それ以外の回転した部品は拒否します。標準行列・字形と幅を検証できるType 3フォントも0.32.0から対応します。幅情報を確認できないフォント、対応表・幅を検証できない独自エンコーディング、対応するCMap以外の縦書き・せん断や反転を含む文字、透明グループなど特殊なForm XObject内の文字、文字を切り欠くクリッピングや複雑なクリップパス、複数の描画命令にまたがるActualText、特殊な描画効果は対象外です。単一の文字描画を持つインラインActualTextは、代替テキストも除去して直接編集できます。標準14書体の未埋め込みType1は、FontDescriptorの有無にかかわらず標準の幅情報を使用します。境界を確認できない圧縮インライン画像や特殊なUserUnit倍率を含むページ、安全に解析できない命令のページも拒否します。置換後は選択したフォントで描き直すため、元の埋め込みフォント・カーニング・横倍率・字形を完全再現するものではありません。
- 「見た目の置換」は元の文字列を保持する背景マスク方式です。検索・抽出で元文字を取得し得ます。背景が単色でないページには適しません。Word型の段落再レイアウト、ベクターの直接編集、未対応形式のContent Stream編集は未実装です。
- Noto Sans JPを同梱し日本語を出力します。静的TTF／OTFの登録と完全埋め込みに対応しますが、システムフォントの自動列挙、TTC・可変・カラーフォント、字詰め・高度な文字組み・縦中横・ルビは未対応です。登録フォントは追加文字・見た目の置換・OCR文字に適用でき、フォーム用フォントの変更は未対応です。欧文標準フォントに日本語を指定すると書き出しエラーになります。日本語と登録フォントの横書きの太字・斜体は見た目を合成します。縦書きでは対応する登録フォントを選びます。自動折り返しは横書きでは幅、縦書きでは高さを使い、タブは4個の空白へ変換します。禁則は基本的な句読点・括弧についての簡易処理です。極端に狭いボックスでは1文字が幅を超える場合があります。画面の標準欧文フォントにはOSの代替フォントを使うため字形が多少異なりますが、行ごとの幅・改行位置は保存用フォントで計算します。完全埋め込みによりPDFとプロジェクトのサイズが増えます。
- 矩形・円・直線・矢印はページ描画として保存します。蛍光ペン・下線・取り消し線・手描きはそれぞれHighlight / Underline / StrikeOut / Ink注釈、付箋はText注釈として保存します。外観ストリームも生成します。文字選択注釈は隣接する文字領域をまとめ、行単位の注釈として保存します。コメント返信スレッドの保持は未対応です。画像と手描きによる署名は「デジタル署名」ではありません。
- しおりの移動先はページまたはhttp・https・mailtoのURLです。ページ内移動先の位置・倍率・表示範囲を保持し、クリック時に反映します。ビューアー倍率は25〜400%です。FitB/BH/BVはページ領域に合わせ、元PDFのcontent BoundingBoxは算出しませんが、PDFに保存する元の倍率・座標は維持します。外部URLしおりは読み込み・編集・PDF/`.kpdf`保存に対応しますが、画面から開きません。Launch/JavaScriptなどのアクションや注釈の返信・Popup関連も保持しません。ページ内の通常のGoToリンクは並べ替え後のページへ再接続し、削除された移動先は除きます。HTTP(S)/mailtoリンクは保持します。
- 編集プロジェクトは展開後512MBまで、内部JSONは16MBまでです。**元PDFや見た目の置換前の内容を含み、暗号化されません。** 墨消し適用済みPDFの代わりにプロジェクトを共有しないでください。破損検出のハッシュは署名・改ざん認証ではありません。
- 一括画像出力は画像の合計512MBまで、各ページ2000万画素まで。印刷は準備する画像の合計1億2000万画素までです。範囲を分けて大きな文書を処理してください。印刷用データは印刷終了イベントか次の印刷準備時に解放します。
- **トリミングは表示領域の変更だけです。** 元の内容の削除には使用できません。
- **墨消しは品質と機能を引き換えにした画像再構成方式です。** 元のContent Stream・画像・OCR・フォーム・添付・メタデータを出力にコピーしません。出力は検索・選択・リンク・フォームのない画像PDFになります。通常最大180 dpi、巨大ページは画素数制限で低下します。領域外の同じ情報、元ファイル、バックアップ、復旧データの削除は保証しません。保存した出力全体を確認してください。ベクターを保つ選択的な安全な墨消しエンジンは未実装です。
- OCRは最大144 dpiで処理し、誤認識や位置ずれがあり得ます。このアプリで追加した認識文字は「OCR校正」で修正できます。既存PDFに埋め込まれたOCR層の校正、縦書きの最適化、手書き認識専用モデルは未実装です。通常PDFを再び開いた場合は元PDFの文字となるため、校正を続けるには`.kpdf`も保存してください。認識文字を修正しても元のスキャン画像は変化しません。
- 復旧状態と登録署名はWebViewのローカルIndexedDBに保存します。**暗号化PDFを開いた場合も復旧データは平文です。** パスワードそのものは復旧状態・履歴・ログへ保存しません。OSのディスク暗号化を必要に応じて併用してください。
- 保存先の一時ファイルは同じディレクトリに作成し、同期後に置換します。通常終了・通常の失敗では削除しますが、電源断/プロセス強制終了での残留やストレージ上の完全消去は保証しません。
- 300ページの高解像度同時描画はしませんが、元のPDFバイト列と編集モデルはメモリーに保持します。常駐PDF処理Workerへバイナリを初回だけコピーして登録し、以後は参照IDで再利用します。Workerの入力キャッシュは256MBを目安に古い入力を解放しますが、処理に必要な入力はこのサイズを超えて保持します。文書切り替えでキャッシュを解放します。数GB級PDF向けの部分読み込み、ディスク上の作業キャッシュ、アプリ全体のメモリー上限管理は未実装です。
- OfficeからPDFの変換には別途Microsoft Officeが必要です。PDFからWordはテキストとして出力します。暗号学的電子署名は `src/security/contracts.ts` に追加プロバイダーの境界を用意しており、署名エンジンは含めていません。

添付ファイルは名前ツリー・文書のAF・ページのFileAttachmentを読み取り、通常保存で保持します。同名ファイルには番号を付けます。追加と取り出しは1件128MBまで。ページ抽出・分割には添付を含めません。外部ファイル参照、PDFポートフォリオの分類、ページや構造要素のAF関連は未対応です。添付を削除したPDFでは参照と対応する埋め込みストリームを除きますが、`.kpdf`・Undo・復旧状態には元データが残ります。機密情報を共有する際は最終PDFを確認してください。

リンクの枠は編集画面だけに表示され、PDFには透明なLink注釈を保存します。新規リンクと変更した文書内リンクはページ全体への移動です。0.9.0では「ツール」→「リンク管理」で既存リンクのX・Y・幅・高さをpt単位で変更でき、「元の配置に戻す」で配置だけを復帰できます。座標は元のCropBoxの左上を基準とし、ページ回転前の値です。配置変更はPDF保存後に反映され、Undo/Redo・`.kpdf`保存にも対応します。0.9.0のインストーラーに含まれます。

## アーキテクチャ

```text
React UI → Command → History / DocumentModel → persistent PDF Worker → native atomic save
               ↑              ↓
          Undo / Redo     local recovery edits + binary store (IndexedDB)

Worker・復旧保存: 編集情報とバイナリを分離し、バイナリは参照IDで再利用

PDF.js Worker: ページ描画、テキスト抽出、検索
Tesseract Worker/WASM: OCR（同梱言語データ）
Rust: ファイル選択・読み書き許可、バイナリIPC、暗号化、原子的置換
```

- `viewer/`: 表示、検索、座標変換、遅延描画
- `text/`: 画面と保存で共有する文字レイアウト、フォント選択、専用Worker
- `fonts/`: ローカルフォント検証、埋め込み権限、登録コマンド、一時FontFaceの管理
- `direct/`: 独自のContent Stream字句解析、元フォントの幅・ToUnicode解析、元文字参照、描画命令の置換。仕様は [PDF Reference](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.6.pdf) に基づき、Adobeの実装コードは使用していません。
- `editor/`: 操作の調整、文書I/O、操作コマンド、復旧・起動・ショートカット・デスクトップ用hook、選択オブジェクト、既存文字エンジン
- `pages/`, `annotations/`, `attachments/`, `links/`, `forms/`, `ocr/`, `redaction/`: 各機能
- `commands/`: モデル変更、履歴、キャンセル
- `state/`: 中央モデル、外部ストア、バイナリ参照、復旧保存とrevision追跡
- `export/`: pdf-lib処理、常駐Worker、入力キャッシュと処理キュー
- `platform/`, `src-tauri/src/`: ネイティブI/O・暗号化
- `components/`: メニュー、ツールバー、サイドバー、ダイアログ、プロパティ

モデルの座標は元ページのCropBoxを基準にした左上原点のptです。ページ回転は別プロパティで管理し、表示と保存時に変換します。元のバイト列はコマンドで書き換えず共有します。保存したリビジョンを識別し、別名保存した後にUndoしても保存先が原本に戻らないようにしています。

## セキュリティ設計

Tauriの権限はウィンドウタイトル・終了・イベントに限定し、汎用shell/任意コマンド実行APIは公開していません。ファイルアクセスはネイティブの選択/ドロップ/起動引数/最近の文書で許可したパスだけです。別名保存先はネイティブダイアログで選び、一度限りのトークンを発行します。通常保存と暗号化・復号のデータはバイナリIPCで渡します。CSPはローカル資産とIPCに限定します。PDFのスクリプトや外部リンクを実行する機能は設けていません。

## 検証結果

検証環境・実行コマンド・結果は [docs/VALIDATION.md](docs/VALIDATION.md) を参照してください。ビルド成功とWindows画面の起動成功は別々に記録します。テストで使用するPDFはコードから生成したデータで、ユーザーの文書は使用していません。

## アプリ名の変更

`src/config.ts` の `APP_NAME` と `src-tauri/tauri.conf.json` の `productName` / ウィンドウ `title` を変更します。アプリの識別子 `io.kikki.pdf` を変えると既存の設定/復旧データの場所も変わります。実行ファイル名も変更する場合は `src-tauri/Cargo.toml` のpackage名を変更してください。
